1. 안전 주의사항

화재·화상 위험: 히터, 덕트 및 건조실 내부가 충분히 식기 전에는 만지지 마십시오. 과열 팝업이 표시되면 원인을 확인하기 전 재가동하지 마십시오.
  • 팬, 히터, 댐퍼 배선과 접지는 전원을 차단한 상태에서 점검하십시오.
  • 제어 온도센서(RS485 주소 100)가 끊어지면 장비가 자동 정지합니다. 이 기능을 우회하지 마십시오.
  • 비상 상황에서는 화면 조작보다 주 전원 차단 장치를 먼저 사용하십시오.
  • 문이 열려도 현재 소프트웨어에서는 히터 제어가 차단되지 않습니다. 문 열림은 상태 알림용입니다.

DY-EP4는 7개 온·습도센서, 로드셀, 팬 전류센서, 도어센서를 1초마다 읽고 팬·히터·댐퍼를 제어합니다.

2.1 온·습도센서 사양

DY-EP4의 온·습도 측정에는 CWT-THxxS Series RS485 Temperature Humidity Sensor를 사용합니다. 다음 값은 제조사 CWT-THXXS TH sensor manual V1.0 기준입니다.

4. 운전 방법

4.1 운전 전 점검

  1. 건조실 내부와 흡·배기 통로에 이물질이 없는지 확인합니다.
  2. 메인 화면에서 제어 온·습도와 팬 전류가 정상 표시되는지 확인합니다.
  3. 도어 상태와 댐퍼 모드를 확인합니다.
  4. 오류 팝업 또는 비정상적으로 어두운 무게 표시가 없는지 확인합니다.

4.2 예열

  1. 예열온도와 예열시간을 ▲/▼ 버튼으로 설정합니다.
  2. 예열 버튼을 누릅니다. 팬과 히터가 운전하며 남은 예열시간이 감소합니다.
  3. 예열시간이 끝나면 준비 상태로 복귀합니다. 중간에 중단하려면 예열 버튼을 다시 누릅니다.

4.3 건조 및 냉각

  1. 설정온도와 건조시간을 지정합니다.
  2. 필요하면 댐퍼를 자동, 열림 또는 닫힘으로 선택합니다.
  3. 건조 버튼을 누릅니다. 버튼은 정지 아이콘으로 변경됩니다.
  4. 건조시간 종료 후 설정된 냉각시간이 0보다 크면 COOL 상태로 전환됩니다.
  5. 운전을 수동 종료하려면 건조 정지 버튼을 누릅니다.
남은 운전 상태는 NVS에 저장됩니다. 단, 안전 오류가 발생하면 남은 시간과 운전 상태가 종료 상태로 변경될 수 있습니다.

5. 자동 제어 방식

온도 히스테리시스

예열과 건조 모두 동일한 설정값을 사용합니다.

  • 현재온도 ≤ 목표온도 − 히스테리시스: 히터 ON
  • 현재온도 ≥ 목표온도: 히터 OFF
  • 두 값 사이: 이전 히터 상태 유지

예: 목표 64°C, 히스테리시스 2°C이면 62°C 이하에서 켜지고 64°C 이상에서 꺼집니다.

자동 댐퍼

  • 습도 ≥ 댐퍼 열림 습도: 완전 열림(100%)
  • 습도 ≤ 열림 습도 − 댐퍼 히스테리시스: 완전 닫힘(0%)
  • 두 값 사이 또는 센서 무효: 이전 상태 유지

예: 열림 50%, 히스테리시스 5%이면 50%에서 열리고 45%까지 내려가야 닫힙니다.

팬 풍속 환산

풍속(m/s) = 현재 ADC × 10 ÷ 팬 10m/s 기준 ADC

기본 기준 ADC는 1135이므로 ADC 1135가 10.0m/s로 표시됩니다.

7. 센서 보정

7.1 온·습도센서

  1. 좌측 온·습도 센서 영역을 길게 누릅니다.
  2. UP/DOWN으로 7개 센서의 온도 또는 습도 항목을 선택합니다.
  3. +/−로 보정값을 0.1 단위로 변경합니다. 온도는 −20~+20°C, 습도는 −50~+50% 범위입니다.
  4. SAVE & EXIT로 저장합니다. EXIT는 변경 전 값으로 돌아갑니다.

7.2 로드셀

  1. 무게 영역을 길게 누릅니다.
  2. 저울을 비우고 ZERO를 누릅니다.
  3. 알려진 기준 추를 올리고 REFERENCE 값을 실제 무게로 맞춥니다.
  4. SET WEIGHT를 누른 뒤 표시값을 확인합니다.
  5. SAVE & EXIT로 저장합니다.

9. 영상 촬영 및 서버 전송

  1. PC에서 http_server 폴더의 서버를 npm start로 실행합니다.
  2. 설정 메뉴의 HTTP IP와 포트가 서버 PC 주소와 일치하는지 확인합니다.
  3. 메인 화면의 회사 로고를 눌러 카메라 프리뷰를 엽니다.
  4. 물체를 화면 중앙의 가로·세로 60% 안내 사각형 안에 고정합니다.
  5. FREEZE 버튼으로 영상을 고정하고 SEND를 누릅니다.
  6. SENDING → SENT 표시를 확인합니다. FAILED이면 네트워크와 서버를 점검합니다.

안내 사각형 내부만 잘라 JPEG 품질 80으로 변환하며 다음 주소로 전송합니다.

POST http://{설정IP}:{포트}/api/dryers/{12자리 장비MAC}/captures
Content-Type: image/jpeg

10. MQTT 및 현재시간

MQTT를 이용하면 서버나 PC에서 장비를 원격 운전하고 센서값과 오류 상태를 받을 수 있습니다. 명령은 반드시 UTF-8의 정상적인 JSON 한 개로 전송해야 합니다.

항목현재 설정설명
브로커mqtt://182.208.84.190:1883암호화되지 않은 일반 MQTT TCP 연결

10.2 장비 MAC 확인 및 토픽 구성

장비 코드는 메인 화면 좌측 하단에 표시되는 Ethernet Base MAC입니다. 콜론(:)을 제거하고 영문을 대문자로 만든 12자리를 사용합니다.

화면 MAC: 80:F1:B2:D3:7D:16
장비 코드: 80F1B2D37D16
방향기능토픽 예시
장비 → 서버주기 센서값dryers/80F1B2D37D16/telemetry
장비 → 서버오류·릴레이·연결 상태 변경dryers/80F1B2D37D16/event
서버 → 장비원격 명령dryers/80F1B2D37D16/command

여러 장비를 한 번에 감시하려면 서버에서 dryers/+/telemetry와 dryers/+/event를 구독할 수 있습니다. 명령은 반드시 대상 장비의 정확한 MAC 토픽으로 발행하십시오.

10.3 원격 명령 JSON

서버는 아래 발행 토픽으로 JSON payload를 QoS 1로 전송합니다. 토픽은 JSON 내부 필드가 아니라 MQTT 메시지의 목적지이며, 예시의 80F1B2D37D16은 실제 대상 장비 MAC 12자리로 변경해야 합니다.

명령필수 필드와 범위발행 토픽완전한 JSON payload 예시

장비 최초 접속 및 서버 등록 순서

  1. 장비가 MQTT 브로커에 연결되면 내부 mqtt_connect 비트가 0에서 1로 변경됩니다.
  2. 장비는 dryers/{장비MAC}/event 토픽으로 mqttConnect:true가 포함된 현재 이벤트 전체값을 전송합니다.
  3. 서버는 토픽의 12자리 MAC을 장비 고유 통신키로 사용하여 등록 장비를 조회하거나 신규 장비를 생성합니다.
  4. 서버는 해당 장비의 command 토픽으로 장비명과 서버 관리용 6자리 장비 ID를 전송합니다.
  5. 장비는 이름과 ID의 형식을 검사한 후 NVS에 함께 저장하고 메인 화면 좌측 하단에 장비이름 / ID 6자리를 표시합니다.
서버 → 장비 토픽
dryers/80F1B2D37D16/command

서버 → 장비 페이로드
{"command":"set_equipment_name","name":"DRYER-01","equipment_id":100001}
필드자료형·범위필수 여부설명
command문자열 set_equipment_name필수장비정보 등록·변경 명령
name비어 있지 않은 UTF-8 문자열
최대 32바이트		필수화면과 이미지 업로드 헤더에 사용할 장비 이름. 한글은 한 글자당 일반적으로 3바이트이므로 바이트 길이에 주의합니다.
equipment_idJSON 정수
100000~999999		필수서버에서 관리하는 6자리 장비 ID
장비 ID는 MAC을 대신하는 MQTT 토픽 키가 아닙니다. MQTT 토픽과 Client ID는 계속 장비 MAC을 사용하고, equipment_id는 서버 업무용 식별값과 화면 표시용으로 사용합니다.
name 또는 equipment_id가 누락되거나, 이름이 UTF-8 기준 32바이트를 초과하거나, ID가 100000~999999 범위를 벗어나면 장비는 명령 전체를 무시하며 기존 장비정보를 유지합니다.
댐퍼 문자열은 영문 소문자만 허용: auto는 습도 자동제어, open은 완전 열림, close는 완전 닫힘입니다. 숫자 0/1/2 또는 한글 문자열은 처리되지 않습니다.

숫자 필드는 JSON 정수여야 합니다. 필드 누락, 범위 초과, 잘못된 명령명, 끝에 다른 문자가 붙은 JSON은 무시됩니다. 명령 큐에는 최대 8개가 저장되며 넘치면 가장 오래된 명령부터 삭제됩니다.

10.4 PC에서 명령 시험

Mosquitto 클라이언트가 설치된 PC에서는 아래와 같이 확인할 수 있습니다. 예제의 MAC은 실제 장비 MAC으로 바꾸십시오.

mosquitto_sub -h 182.208.84.190 -p 1883 -q 1 -t "dryers/80F1B2D37D16/#" -v

mosquitto_pub -h 182.208.84.190 -p 1883 -q 1 \
  -t "dryers/80F1B2D37D16/command" \
  -m '{"command":"set_temp","temp":64}'

Windows 명령 프롬프트에서는 줄바꿈 문자(\) 없이 한 줄로 실행하십시오. PowerShell에서는 JSON 따옴표가 변형되지 않도록 위와 같이 작은따옴표로 전체 페이로드를 묶습니다.

10.5 텔레메트리 메시지

설정 메뉴의 MQTT 전송 주기(기본 5분)마다 최신 1초 센서 스냅샷을 발행합니다. 이 정규 주기와 별도로, 장비가 서버에서 유효한 command를 수신하여 처리하면 해당 명령의 제어 출력을 적용한 직후 텔레메트리를 한 번 즉시 발행합니다. 따라서 서버는 다음 정규 전송 시각까지 기다리지 않고 명령 적용 후 상태를 확인할 수 있습니다.

명령 응답 텔레메트리: 정상적으로 파싱되어 명령 큐에서 처리된 명령만 즉시 전송을 발생시킵니다. 잘못된 JSON, 알 수 없는 명령 또는 범위를 벗어난 필드는 무시되며 응답 텔레메트리를 발생시키지 않습니다. 즉시 전송은 기존 MQTT 전송 주기 카운터를 초기화하지 않습니다.

MQTT가 끊긴 동안에는 전송을 건너뛰며, 연결되지 않은 상태에서 명령 응답 또는 정규 텔레메트리를 발행할 수 없습니다.

10.6 이벤트 메시지

장비는 1초마다 현재 16비트 이벤트값과 이전 값을 XOR 비교합니다. 하나 이상의 비트가 바뀌면 전체 현재 상태를 dryers/{MAC}/event 토픽으로 즉시 발행합니다. 오류 발생(false→true)뿐 아니라 오류 해제(true→false)와 릴레이 ON/OFF 변화도 전송됩니다.

전송 조건전송 방식참고
16개 비트 중 하나 이상 변경QoS 1, Retain 사용 안 함주기 전송이 아니라 상태 변경 시 전송
여러 비트가 같은 1초 주기에서 변경현재 전체 상태를 JSON 한 건으로 전송변경된 비트만 보내는 형식이 아님
MQTT 연결이 끊어진 상태발행 생략오프라인 이벤트를 별도 저장·재전송하지 않음
MQTT 재연결mqttConnect:true 상태 변경 이벤트 발행서버는 재접속 시점으로 활용 가능

이벤트 JSON에는 장비 시간이나 sequence가 포함되지 않습니다. 이벤트 발생시각이 필요하면 MQTT 서버 수신시각을 기록하십시오.
현재 펌웨어는 명령 전용 ACK 토픽을 발행하지 않습니다. 유효한 명령을 처리한 직후 발행되는 telemetry에서 변경된 설정값·운전상태·릴레이 상태를 확인하십시오. 관련 이벤트 비트가 변경된 경우에는 event도 별도로 발행됩니다.

10.7 연결 문제 확인

  1. 장비 화면에 MAC이 정상 표시되는지 확인합니다.
  2. 장비와 브로커 사이의 Ethernet 링크, IP, 게이트웨이 및 DNS를 확인합니다.
  3. PC에서 브로커의 TCP 1883 포트에 접근 가능한지 확인합니다.
  4. 토픽의 MAC에서 콜론을 제거했는지, 대문자 12자리인지 확인합니다.
  5. JSON 키 이름과 영문 소문자 명령값을 확인합니다.
  6. MQTT 재연결 후 mqttConnect:true 이벤트 또는 시리얼 로그의 구독 메시지를 확인합니다.

10.8 현재시간

현재시간은 MQTT 서버에서 받지 않습니다. 네트워크 연결 후 NTP pool.ntp.org에서 동기화하며 한국 표준시(KST, UTC+9)를 표시합니다. MQTT가 정상이어도 인터넷 DNS 또는 NTP가 차단되면 시간이 표시되지 않을 수 있습니다.
